# Логика сервиса Excel JSON Packets

Документ описывает текущую логику сервиса, чтобы можно было быстро вспомнить, как Excel превращается в JSON-пакеты ЭТРАН и Postman-коллекцию.

## Назначение

Сервис принимает Excel-файл ЭТРАН через веб-интерфейс, читает листы шаблона и формирует один JSON-файл `waybill-packages.json` со всеми накладными. Дополнительно UI умеет скачать Postman-коллекцию, где каждая накладная отправляется отдельным POST-запросом.

## Запуск

Основной запуск через Docker:

```bash
docker compose up -d --build
```

После запуска UI доступен по адресу:

```text
http://localhost:8081/
```

## Основные файлы

- `src/main/java/local/parser/api/ConvertController.java` - HTTP endpoint `/api/convert`, выбор режима обработки и формирование ответа.
- `src/main/java/local/parser/excel/ExcelReader.java` - чтение Excel, определение ЭТРАН-шаблона, чтение листов.
- `src/main/java/local/parser/etran/EtranWaybillMapper.java` - маппинг строк Excel в структуру `waybill`.
- `src/main/resources/static/index.html` - UI загрузки файла.
- `src/main/resources/static/app.js` - логика UI, скачивание JSON и Postman-коллекции.
- `src/main/resources/application.properties` - настройки Spring, включая скрытие `null`-полей.

## Определение ЭТРАН-шаблона

Файл считается ЭТРАН-шаблоном, если в нем есть:

- лист `Свод данных`;
- лист `Накладная` или `Накладные`.

Если шаблон распознан как ЭТРАН, сервис использует `EtranWaybillMapper`. Если нет, файл обрабатывается старой универсальной логикой пакетирования строк в `packet-0001.json`.

## Чтение Excel

Для ЭТРАН-шаблона читаются два листа:

- `Накладная` или `Накладные`;
- `Свод данных`.

Первая строка считается заголовками. Вторая строка с подсказками пропускается. Данные начинаются с третьей строки.

Связь между листами выполняется по номеру накладной:

- `Накладные.Номер`;
- `Свод данных.Номер накладной ЭТРАН`.

Если на листе накладных только одна строка, она может применяться ко всем строкам свода.

## Формирование JSON

Сервис формирует один файл:

```text
waybill-packages.json
```

Внутри файла массив объектов, где каждый объект соответствует одной накладной:

```json
[
  {
    "waybill": {
      "waybill_status": "В пути"
    }
  }
]
```

Группировка идет по номеру накладной. Все строки с одинаковым номером накладной собираются в один объект `waybill`.

## Null-поля

Сейчас `null`-поля не выводятся в JSON. Это задается настройкой:

```properties
spring.jackson.default-property-inclusion=non_null
```

Если ее убрать, `null`-поля снова будут попадать в JSON.

## Маппинг листа "Накладная" / "Накладные"

| Excel | JSON |
| --- | --- |
| `Номер` | `waybill.waybill_number` |
| `Идентификатор` | `waybill.waybill_identifier` |
| `ЕСР станции отправления` | `waybill.departure_station_code` |
| `ЕСР станции назначения` | `waybill.destination_station_code` |
| `Код плательщика` | `waybill.payer_code` |
| `Наименование плательщика` | `waybill.payer` |

Кавычки в значениях, например в названии плательщика, корректно экранируются JSON-сериализатором.

## Значения по умолчанию

| JSON | Значение |
| --- | --- |
| `waybill.waybill_status` | `В пути` |
| `waybill.delivery_deadline` | `2026-04-16T00:00:00Z` |
| `waybill.submitted_at` | `2026-03-30T02:55:27Z` |
| `waybill.approved_at` | `2026-03-06T11:35:58Z` |
| `waybill.accepted_at` | `2026-03-30T11:39:55Z` |
| `waybill.cargo_accepted_at` | `2026-03-30T11:39:55Z` |
| `waybill.departure_at` | `2026-03-30T11:57:50Z` |

`waybill.waybill_created_at` генерируется текущей датой и временем в момент загрузки файла.

## Вагоны

Массив:

```text
waybill.waybill_railway_carriage[]
```

| Excel, лист `Свод данных` | JSON |
| --- | --- |
| `Номер вагона` | `railway_number` |
| `Род вагона` | `sort` |
| `Грузоподъемность вагона, кг` | `railway_lifting_capacity` |

`Грузоподъемность вагона, кг` делится на `1000`.

Преобразование рода вагона:

| Excel | JSON |
| --- | --- |
| `Платформа 40 - футов` | `Пл. для КТК, колесн. техн.и конт.-цистер` |
| `Платформа 60 - футов` | `ПЛ для КТК длиной  19,62` |
| `Платформа 80 - футов` | `ПЛ для КТК длиной  свыше  25,5` |

Вагоны внутри накладной уникализируются по номеру вагона.

## Контейнеры

Массив:

```text
waybill.waybill_container[]
```

| Excel, лист `Свод данных` | JSON |
| --- | --- |
| `Номер вагона` | `carriage_number` |
| `Номер КТК` | `container_number` |
| `Грузоподъемность КТК, кг` | `lifting_capacity` |
| `Масса тары, кг` | `weight` |
| `Тип КТК` | `length` |
| `Масса нетто  КТК, кг` | `weight_net` |

`Грузоподъемность КТК, кг` делится на `1000`.

`Масса тары, кг` не делится и передается как пришла из Excel.

Дополнительно для каждого контейнера всегда заполняются:

| JSON | Значение |
| --- | --- |
| `etran_container_type_id` | `10` |
| `iso` | `8` |

Преобразование типа КТК:

| Excel | JSON |
| --- | --- |
| `Стандартный 40` | `40` |
| `Стандартный 20` | `20` |

Контейнеры внутри накладной уникализируются по номеру КТК.

## ЗПУ

Массив:

```text
waybill.waybill_zpu[]
```

| Excel, лист `Свод данных` | JSON |
| --- | --- |
| `Номер КТК` | `container_number_zpu` |
| `Номера ЗПУ` | `zpu` |

Если в ячейке `Номера ЗПУ` несколько значений через запятую, создается несколько объектов `waybill_zpu`.

Если Excel превратил несколько числовых ЗПУ в значение вида `123.456`, точка заменяется на запятую и значения разделяются.

## Грузы

Массив:

```text
waybill.waybill_product[]
```

| Excel, лист `Свод данных` | JSON |
| --- | --- |
| `Код груза ЕТСНГ` | `etsng_code` |
| `Масса брутто груза, кг` | `cargo_weight` |

Для `Код груза ЕТСНГ` берутся только цифры до первого пробела. Например:

```text
461027 АМИНОПЛАСТЫ -> 461027
```

Логика количества грузов:

- если в накладной несколько КТК, `waybill_product` заполняется одним грузом;
- если в накладной один КТК, `waybill_product` заполняется всеми грузами из строк Excel.

## Postman-коллекция

В UI есть поля:

- `URL Datareon`;
- `Логин`;
- `Пароль`.

Кнопка `Скачать Postman` формирует коллекцию `waybill-postman-collection.json`.

В коллекции:

- один request на каждую накладную;
- метод `POST`;
- body каждого request содержит JSON одной накладной;
- авторизация задается как Basic Auth на уровне коллекции.

Если URL, логин или пароль не заполнены, используются переменные:

```text
{{datareon_url}}
{{datareon_login}}
{{datareon_password}}
```

## SQL-файлы

В проекте также есть SQL-файлы для разовых обновлений `net_weight` по файлу `Шаблон Владивосток 56.xlsx`:

- `update_net_weight_by_waybill_vladivostok_56.sql`;
- `update_net_weight_vladivostok_56.sql`;
- `update_weight_net_vladivostok_56.sql`.

Актуальный вариант для связи через вагоны:

```text
update_net_weight_by_waybill_vladivostok_56.sql
```

Он использует связь:

```sql
alis.waybill -> waybill_railway_carriage -> waybill_container
```

и ограничивает накладные датой:

```sql
w.waybill_created_at = TIMESTAMP '2026-05-29 07:18:10.000'
```
